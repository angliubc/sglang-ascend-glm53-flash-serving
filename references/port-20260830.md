## aarch64 trap (cost one wasted 17GB transfer)
- 910B = Kunpeng aarch64; workstation pull of quay multi-arch → amd64 image; ran fine locally (native), useless on NPU
- x86_64 tokenizers/safetensors wheels rejected ("not a supported wheel") while pure-python wheels installed fine — symptom pattern for arch mismatch
- Fix: `docker pull --platform linux/arm64` (arm64 image is only 6.3GB vs 17GB amd64), aarch64 tokenizers wheel (`tokenizers-0.23.1-cp310-abi3-manylinux_2_17_aarch64...whl`), binfmt for cross-arch build RUN steps

## quay.io flaky blob debug transcript
- `docker pull --platform linux/arm64` stalled forever ×2 (zero RX, /proc/net/dev static, docker tmp empty) — same on the CUDA host
- manifest API fine (200; arm64 digest present); blob with token+range: config blob → 302 (normal), 4.1GB layer → 404 body 86B; minutes later all 19 layers 302; then same layer 404 8/8 → **inconsistent backend replicas** (Aug 29 push not fully replicated)
